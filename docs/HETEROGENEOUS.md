# 异构计算方向（算子化 · 自由组合 · 暴力择优）

> 状态：方向记录（2026-10-08，工作站实验前置）。**不属于 v1.0 承诺范围**——
> 是下一个阶段的方法论纲领。

## 主张

- **一切皆算子**：标量直算、编排器+列块、全开码、进位保存（CSR）、
  Vector API（JDK 25 孵化）、AVX/GPU 异构——统一到"同签名的算子"：
  `op(a, b, out)`（零分配优先），实现可插拔；
- **自由组合**：宽度 = 128/256 原子 × 组合器的任意拼装；算法路径（schoolbook /
  Karatsuba / CSR）是参数不是代码分支；
- **暴力择优**：不做先验判断——全部上 JMH/跨平台实测，按"负载 × 机器"选最强。
  **昨日结论可被明天数据推翻**（本库已有先例：mulBoth、768/1024 mulHigh 都是数据翻案）。

## 与既有结论的关系

- 本库已实测画出两条边界，**边界内就是待测的算子空间**：
  1. 内联树 ≤ C2 预算 → 组合胜利；超预算 → 循环引擎胜利（Round G）；
  2. EA 覆盖局部链 → 不可变 API 已零分配（Round F）。
- SIMD 从"冻结"升级为"算子候选"；**标量仍是唯一 oracle**（三路对拍的最后裁判）。
- 约束不变：三路对拍守门、CPU 锁核测量、无收益即回退、负结果存档。

## 工作站首批实验（草案）

1. **算子接口原型**：把现有 128/256 的实现包装成统一算子签名，跑通"同场竞技"框架；
2. **Vector API 算子 vs 标量**：128/256 的加/位运算/移位先行（无进位依赖的算子先打）；
3. **进位保存链算子**：直击 `mulFull` 链延迟（本库挂账 #4 的触发条件由工作站剖析提供）；
4. **JMH 矩阵**：宽度 × 算子 × 实现，自动生成跑批 + 结果落表（对齐 `docs/BENCH.md` 口径）。

## 纪律（继承）

一次一变量；先写期望再跑；锁核；无提升回退；负结果必须存档——
**"有验证的散装 = 绿皮科技"**。
