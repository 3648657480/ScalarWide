# ScalarWide 设计文档

> 决策与验收的权威记录。实验数据记在 `docs/BENCH.md`。

## 1. 背景与目标

为"宽域坐标 / 大数 key"（V2 方向）准备的**纯标量定点大数库**。
社区已有反馈："fastutil 没有 Long128、自建 128bit key 性能差"——
本库的目标就是用**可复现的基准 + 对拍**把这条路走通：
key 场景（128/256）先落地，384 兜底，SIMD 冻结为实验。

## 2. 决策（2026-10-08）

| 决策 | 内容 |
|---|---|
| 宽度 | 128（key 甜点）+ 256（通用）+ 384（兜底，正确性 P0 性能 P1）；512 挂起 |
| SIMD | 不做（标量是 oracle；AVX2/AVX-512 寒假再评估） |
| 乘法 | **纳入 v1**（`Math.unsignedMultiplyHigh`，256/384 走 schoolbook） |
| 语义 | 二补码、算术 2^N 回绕；`compareTo` = 无符号（key 友好）；移位量 `[0,N)` 校验 |
| 第一用例 | 128/256-bit key：`hashCode` / `equals` / `compare` 极致快（哈希已直接实现，不经过引擎分配） |
| 仓库 | 本地优先（`C:\Project-ScalarWide`），跑通后再决定公开 |

## 3. 架构

- `Limbs`（包私有）= **通用参考引擎**（long[] 小端 limbs；加减进位/借位无分支、
  移动、比较、schoolbook 乘法、BigInteger 桥）。所有宽度的正确性基线。
- `Wide128/256/384` = 类型化公开 API（final 字段 l0..lN；`limb(i)` / `of` /
  `fromBigInteger` / 运算 / `toString`）。当前接线到 `Limbs`（**基线允许分配**，
  这是有意的：附魔轮以它为前后对照）。
- 例外：`hashCode` / `equals` / `bitLength` 从一开始就无分配直算（key 热路径，
  若也走引擎分配会让基线失真到没有参考价值）。

## 4. 验收标准（v1.0 目标）

| 宽度 | 运算 | 验收 |
|---|---|---|
| 256 | 加减 | 正确性 P0；性能 ≥5× BigInteger |
| 256 | 位运算 | 正确性 P0；性能 ≥8× BigInteger |
| 256 | 移位 | 正确性 P0（边界 k=0/63/64/127/128/191/192/255） |
| 256 | 乘法 | 正确性 P0；性能目标实测定标 |
| 128 | 全部 | 正确性 P0；key 路径（hash/equals/compare）性能实测定标 |
| 384 | 全部 | 正确性 P0；性能 P1 |

## 5. 附魔阶梯（一次一变量，JMH 前后对照）

1. **寄存器化 + 手动展开**：128/256 的 add/sub/移位/乘法去掉数组与循环。
   （0.2.0 已完成：256 全运算 2.3–4.4×，128 mul 5.7×；数据见 `docs/BENCH.md`。）
2. **零分配 API**：`*Into(a, b, out)` 输出参数风格；对象池；SoA 布局。
3. **内联验证**：`-XX:+PrintInlining` 确认热点真被 C2 编译。
   （注意：`@ForceInline` / `@Stable` 是 JDK 内部注解，公开库不可用——
   用方法粒度与内联验证替代，不引 `--add-exports`。）
4. **`VarHandle` 评估**：仅当 JIT 未消除边界检查且实测有收益才上（大概率省下）。
5. 备而不用：`Unsafe`、JNI/GMP。

## 6. 验证协议

- **对拍**：每个运算 × {全极端值两两组合，固定种子 12345 随机 5000 对} × 3 宽度；
  另测移位边界与构造器边界（拒绝负数/超宽）。
- **基准**：JMH（`src/jmh`），同场 BigInteger 对照（值取非负高位以避免符号干扰），
  基线数字与命令记入 `docs/BENCH.md`。
- **零分配验收**：JFR 采样（附魔轮 2 之后）。
- 结论只在"同一命令、同一机器、同一版本"内有效。

## 7. 已知边界

- 本库不覆盖 1e306 原始坐标（≈1020 bit）；那是"大数坐标 + 局部窗口"分层设计的活。
- 384 位乘法为 6×6 schoolbook（36 项），性能目标 P1。
- v0.1.0 的运算路径分配较多（基线）；这是附魔轮的起点，不是最终形态。
