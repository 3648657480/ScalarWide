# ScalarWide 设计文档

> 决策与验收的权威记录。实验数据记在 `docs/BENCH.md`。

## 1. 背景与目标

为"宽域坐标 / 大数 key"（V2 方向）准备的**纯标量定点大数库**。
社区反馈："fastutil 没有 Long128、自建 128bit key 性能差"——
本库目标：用可复现基准 + 三路对拍把这条路走通。key 场景（128/256）先落地；
384/512/768/1024 走"双原子组合"；SIMD 冻结为实验。

## 2. 决策记录

### 2026-10-08 · 首轮

| 决策 | 内容 |
|---|---|
| 宽度 | 128（key 甜点）+ 256（通用）+ 384（兜底）；512+ 后补 |
| SIMD | 不做（标量是 oracle；寒假再评估） |
| 乘法 | v1 纳入（`Math.unsignedMultiplyHigh`） |
| 语义 | 二补码、2^N 回绕；`compareTo` 无符号；移位 [0,N) 校验；乘低半/高半/全积语义进 Javadoc |
| 基线 | 允许分配（附魔起点），逐轮消除 |

### 2026-10-08 · 二轮（v2 结论落地）

| 决策 | 内容 |
|---|---|
| 根本判断 | 定长（编译期常量）是根：无循环/无边界检查/可内联；分配是当下最大项，零分配轮后重估 |
| 双原子 | 128/256 为原子；384=3×128；512/768/1024=n×256；到原子递归深度 ≤1（Karatsuba 手动展平） |
| 套娃红线 | **算法层套娃，禁止对象层嵌套**：表示永远是扁平 limb（l0..lN），组合只发生在算法/位运算序列 |
| 乘法原语 | 原子层只有 `mulFull`（128→Wide256、256→Wide512）；更高宽度由组合 + Karatsuba 框架生成（阈值实测） |
| 进位原语 | `Carry.addCarryOut` / `Carry.subBorrowOut` 唯一定义点 |
| API 双轨 | 对象 API（人用）+ SoA 静态 API（映射/热路径；key 路径禁池化）——附魔轮 2 落地 |
| 内联 | 约束是**字节码尺寸**（MaxInlineSize 35B / MaxFreqInlineSize 325B），不是深度；PrintInlining 探针提前到 1.6 之前 |
| hash 缓存 | 存疑：与"对象头是头号敌人"冲突；先 JOL 尺寸 + cold/warm 对拍再定（可能只给 256+/key） |
| 基准口径 | mul 低半 ≠ BigInteger.multiply 全积；BigInteger 缓存 hashCode；一切比值必须标口径 |
| BigInteger | 不加入库内（test-only oracle） |

## 3. 架构

- `Carry`：原子层进位/借位原语（唯一定义点）。
- `Limbs`（包私有）：通用参考引擎 + **常驻内部 oracle**（三路对拍：实现 vs Limbs vs BigInteger）。
- `Wide128/256`：原子，寄存器特化（无数组/循环）；`mulFull` 单趟进位链。
- `Wide384/512`：扁平 limb，当前引擎背底（正确性优先）；待组合化（1.5）。
- 零分配形态（轮 2）：`*Into(a,b,out)` + SoA 静态 API。

## 4. 验收标准（预期 + 实测）

实测 = 2026-10-08 锁核 JMH（对象 API 口径；详见 `docs/BENCH.md`）。

| 宽度 | 运算 | 验收 | 预期 vs BigInteger | 实测 vs BigInteger |
|---|---|---|---|---|
| 128 | 加减 | 正确性 P0 | 3–8× | add 3.7× / sub 4.4× |
| 128 | 位运算 | 正确性 P0 | 4–8× | and 3.8× / shl 3.5× / ushr 3.0× |
| 128 | mul | 正确性 P0 | （口径未定） | mulFull 3.1×（全积口径，0.3.0 首测）；mul(低半) 5.9× |
| 256 | 加减 | P0；性能 ≥5× | 2–6× | add 2.5× / sub 2.6× |
| 256 | 位运算 | P0；性能 ≥8× | 3–6× | and 2.8× / shl 2.5× / ushr 2.5× |
| 256 | mul | 正确性 P0 | （口径未定） | mulFull 1.02×（全积口径，与 intrinsic 持平） |
| hash/compare | 全部 | 正确性 P0 | 5–10× / 4–8× | 未锁核实测；cold/warm 口径待定 |
| 384/512 | 全部 | 正确性 P0，性能 P1 | 1.5–4× / 2–4× | 引擎背底，未测 |

注：≥5× / ≥8× 为"附魔完成后（含零分配）"目标；当前值为"附魔中"（每调用 1 次结果分配）。

## 5. 附魔阶梯（v2 最终 + 探针修订）

1. **原子到极致**：字段化、手写 `mulFull`、无分支进位。（0.2.0 / 0.3.0）
1.4 **拆小方法（0.4.0 已完成）**：编排器（mul 56B / mulFull 92B）+ 列块（≤243B）全部热内联；
    `MulAcc` 被 EA 抹除（分配率 80.001 B/op 不变）；性能中性（调用开销非瓶颈）——
    组合地基就位，价值待 1.5 实测。
1.5 **套娃框架**：384 = 3×128；512/768/1024 = n×256（扁平表示 + 原子原语组合）。
    （512、384、768、1024 的 `mul` 全部完成：384 10.2×、512 3.15×、768 1.98×、1024 1.43×（均 vs 自家引擎）；
     vs BigInteger：384/512 领先，768/1024 落后 1.4-1.8×——"大宽度低头"实测确认。
     剩余：768/1024 的 `mulHigh`。）
1.6 **堆法套娃**：Karatsuba 展平为位运算 + 原子序列；**阈值实测**（叶子调用开销 vs 节省的乘积）。
1.7 **布局**：JOL 测占用；512 优先单缓存行；字段顺序与 hash 缓存一并定。
    （**JOL 测量完成（0.9.0+，见 `docs/LAYOUT.md`）**：头 16B；512 对象 80B 跨 2 行（单行目标
    仅 SoA/Valhalla 可兑现）；hash 缓存成本：128 +25%、256 +16.7%、512 +10%、1024 +5.6%。）
2. **零分配 API**：`*Into(a,b,out)` + SoA 静态 API；key 路径禁池化。
    （首期落地（0.10.0）：**MutableWide128/256 载体**（对象风）；实测：EA 已覆盖局部链——
    载体收益限于跨方法/字段驻留 scratch（BENCH Round F）。SoA 轨道留待映射层。）
3. **内联验证**：已在 0.3.0 提前完成探针（`docs/INLINE.md`）：128 全链可内联；
    256 巨石（473/1000B）不可内联 → 触发 1.4。
4. **VarHandle 评估**：仅当 JIT 未消除边界检查且实测有收益。
5. 备而不用：`Unsafe`、JNI/GMP。

## 6. 验证协议

- **对拍（硬门禁）**：每个运算 × {极端值两两组合，种子 12345 随机 N 对} × 全宽度；
  `mulFull` 与派生视图一致性；**三路 oracle**：寄存器实现 vs `Limbs` 引擎 vs BigInteger。
- **基准**：JMH；**CPU 亲和锁定**（`start /b /wait /affinity 1`）；
  `-wi 5 -i 10 -f 1 -w 500ms -r 500ms`；比值必须标注口径。
- 每扩一档宽度 = 一轮新实验（不允许"继承信任"）。
- 结论只在"同一命令、同一机器、同一版本"内有效。

## 7. 已知边界与风险

- 不覆盖 1e306 原始坐标的完整宽度（≈1017 bit，由 1024 档承接）。
- 本库不做除法（坐标 → chunk/region 走 2 的幂移位）；此假设进文档。
- 乘法 vs `multiplyToLen` intrinsic：对象 API 口径我们领先；纯吞吐/大宽度口径待测，只定标不设硬倍数。
- 套娃内联失败风险：对策 = 拆小方法 / 紧凑循环体 / 实测接受；`PrintInlining` 判定。
- Karatsuba 展平正确性：三路对拍兜底。
- `toString`：JDK 18+ 的 `BigInteger.toString` 已分治化，先借用；自研暂无必要。
- Valhalla 未落地：512 单行目标接受跨行，未来迁移。
- **已知限制（0.6.2）**：`Wide512.mulHigh` 分配已修复（832→80 B/op）；时间仍差
  BigInteger 约 1.6×（137 vs 86ns）——四季积串行链未重叠，待汇编级剖析。
